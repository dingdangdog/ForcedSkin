# 011 浏览器扩展 SPA 跳转与悬停稳定性修复

## 问题根因

- 动态节点观察器会把 `childList` 变化的父节点作为深度处理根节点。Cloudflare Dashboard 等网站把图表 tooltip、弹层和路由内容挂载到 `body` 或大型容器时，一次很小的变化会退化成整页样式恢复、扫描和重写，造成背景闪变、主线程占用和 SPA 路由渲染延迟。
- 为捕获延迟创建的 Shadow Root，扩展曾在页面主世界覆盖 `Element.prototype.attachShadow`。即使包装逻辑本身很小，修改网站原生 DOM 原型也可能破坏组件框架的原生方法判断或生命周期，不应作为通用主题引擎的默认行为。
- 自动枚举并覆盖网站根节点全部颜色型 CSS 自定义属性会扩大插件与网站运行时状态的耦合，图表和组件库可能在交互时读取这些令牌并重新绘制。

## 修复内容

- 完全移除主世界脚本和 `attachShadow` 原型覆盖；扩展只在隔离世界运行，不再修改网站 JavaScript 运行环境。
- 新增节点只深度处理新增子树，不再处理其大型父容器。
- `class` 状态变化只同步处理目标元素自身，不再恢复和扫描整棵后代树。
- 适配器候选节点与通用主题候选节点分开收集；父容器仅参与轻量选择器匹配，不参与通用深度改色。
- 增量刷新不再重复写入 `html` / `body` 根内联样式，减少网站 MutationObserver 收到无意义样式变化的概率。
- 路由卸载的大型 DOM 子树不再在 MutationObserver 回调中同步遍历；改为空闲时间按批清理样式状态，避免阻塞 SPA 后续渲染。
- 移除对网站任意 CSS 自定义属性的枚举和内联覆盖，保留插件自有变量、通用规则和逐元素主题映射。
- 保留开放 Shadow DOM 支持：同步创建并随宿主插入的 Shadow Root 会在新增子树扫描时注册，初始页面会在 DOM 就绪后完整补扫。

## 涉及文件

- `extension/manifest.json`
- `extension/src/content/engine.js`
- 删除 `extension/src/content/shadow-hook.js`
